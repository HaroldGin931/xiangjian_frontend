# 乡建前端

当前实现从已上传 V11 提交 `5b40a14` 继续实现已确认的最小原型。使用 TanStack Start、Astryx 与现有组件；普通帖子属于 PDS，任务、活动、社区和稻米属于 Rice。

## 本地运行

安装依赖：

```bash
npx --yes pnpm@10.17.1 install
```

先准备隔离 Rice/PDS 网关，再启动前端。本轮验收使用网关 19016、前端 19017：

```bash
XIANGJIAN_BACKEND_URL=http://127.0.0.1:19016 npm run dev -- --port 19017
```

访问 `http://localhost:19017`，登录统一使用 `localhost`。不指定参数时仍使用旧默认网关 19006、前端 19007；请按需要选择，避免混用两套测试数据。Vite 将 `/api/attachments` 与固定的 `/pds/xrpc/com.atproto.sync.getBlob` 转发到 `XIANGJIAN_BACKEND_URL`，分别读取 Rice 附件与 PDS 原图。其他 Rice/PDS 请求由 TanStack 服务端函数转发，两套令牌分别用于对应服务。

## 当前实现范围

- **全局搜索**：帖子、任务、活动、社区、用户五组结果默认展开，可独立收起；新关键词恢复展开，空结果保留提示。帖子使用 Post Cache，其他四类读取 Rice；用户按昵称或账号搜索，点击打开个人主页浮窗。用户分页只返回公开资料，不搜索联系方式。

- **页面与发布**：广场、任务、活动、我的四个底栏入口；顶部全局搜索和通知。发布浮窗按所在页面默认选中发帖、发任务或发活动，切换类型保留各自输入。手机随视口收窄，桌面内容最大宽度 760px。
- **普通帖子**：读 Post Cache，使用 PDS 发布、回复及既有互动；在正文输入 `#话题`，不单列话题字段。发布结果直接使用 PDS 返回的真实记录更新缓存，后续由索引读取校准。重试复用本次帖子的记录键，避免网络响应丢失后重复创建。
- **关闭与草稿**：未保存时点击外部、关闭、Escape 或站内离开，显示视口居中的“保存草稿／直接关闭”提示；关闭提示返回编辑，保存失败保留内容。帖子正文、图片文件及发布重试键按 PDS DID 保存到当前浏览器 IndexedDB，重开自动恢复，发布成功清除；不上传帖子草稿图片。任务、活动沿用 Rice 草稿与其校验。直接关闭只放弃本次未保存编辑，保留旧草稿。
- **正文与图片**：帖子、任务、活动共用选图预览、移除、列表首图、详情图片组和放大浮窗；任务、活动最多九张，帖子暂按标准 `app.bsky.embed.images` 保持四张。原图每张 20 MB（20,000,000 bytes），支持 JPEG/PNG/WebP/GIF。选择文件时只创建本地预览，保存或发布时才上传。帖子静态大图在浏览器压缩至本部署 PDS 的 1 MB 上限，GIF 超限明确提示，不转成静态图；使用 PDS `uploadBlob`。任务/活动使用 Rice 附件，`attachment_ids` 与草稿正文一起保存，重新打开恢复顺序。部分上传失败会保留输入，重试复用已成功上传的文件。
- **单人任务**：只有所属社区的管理员可以发布；草稿包含交付要求、申请截止、交付截止与报酬。发布前保存服务端草稿，余额不足时可恢复继续编辑。申请、选定一人、提交成果、退回重交、一次验收并发放和任命前取消均调用 Rice。申请截止只停止新申请；执行逾期保留任务与冻结资金，并提供负责人入口。发布后核心约定锁定，保存后的草稿社区也保持固定。
- **我的任务**：合并本人管理、申请和承接的记录，管理员也能回访在其他社区参与的任务。候选选择显示“待审批”，成果待验收显示“审核中”；未入选归入已结束。
- **活动**：使用独立 `/api/events`，包括草稿、发布、申请、候选通过/拒绝/移除、取消及主办方确认结束。申请与通过人数分别显示；动作入口以服务端允许动作为准。免费与测试稻米活动共用候选审批流程，付费申请、未入选退款及结束结算由 Rice 原子处理；不再用普通帖和评论模拟活动报名。
- **社区**：创建者可将已有成员设为管理员或撤销其管理员身份，多名管理员共同管理本社区的新任务、活动与入会申请；草稿仍仅作者可见。社区身份显示本人所在社区和角色；联盟与治理进入节点目录，详情保留社区成员、本人申请结果、管理员待审批名单和社区动态入口。加入申请资料仅申请本人及管理员可见，不在公开社区进展中展示。
- **联系方式与访客**：发布任务、活动必须填写公开的组织方联系方式，申请时必须填写仅本人及有管理权限的组织方可见的联系方式。草稿允许暂不填写，历史记录不补造联系信息。访客可在可参与详情直接登录并返回原详情；“可申请”筛选先说明登录要求。金额保留原输入，负数、小数显示错误并阻止提交。
- **节点稻米**：管理员在“我的”卡片切换“我的测试稻米／节点稻米”，多个社区按名称选择，余额与流水跟随所选账户；普通成员不显示社区钱包入口。个人账户保留，新社区账户从零开始；管理员可明确确认从个人账户转入。新任务从社区账户冻结和支付，活动费用结算到社区。已有个人冻结款仍由原发布者管理和结算，旧草稿首次发布采用社区账户。
- **个人与稻米**：保留个人主页、编辑资料、头像、退出登录；显示真实可用余额、冻结余额、累计获得和分页明细，退款不重复计入累计获得。任务/活动的公开履历与本人私有申请记录分别读取。
- **通知**：合并 Rice 任务/活动/社区通知与既有 PDS 通知，点击单条标为已读并进入相应详情，只有未读行显示底色。“清除所有已读消息”保留未读；单条已读和清除按账号保存在当前浏览器。“全部已读”沿用两端接口，某一来源失败时保留该来源的未读状态。

所有写操作均使用真实接口，无演示身份切换或模拟成功。本轮只用于隔离测试账号、测试稻米与测试记录；不开放真实成员资产。小队、邀请、管理员交接、任务任命后取消/换人/延期、商品和私信不在本次最小范围内。

社区钱包的读取顺序是 [“我的”路由](src/routes/me.index.tsx)预取管理的社区和钱包 → [个人页面](src/features/profile/ProfilePage.tsx)切换当前账户 → [稻米明细](src/features/grains/GrainHistoryPage.tsx)复用同一快照。使用现有 `/api/nodes?mine=managed` 与 `/api/nodes/:id/wallet`，缓存按账号和登录会话隔离；社区请求失败时保留个人数据，显示错误，不用零余额代替失败。

## 注册与 Semi

登录方式读取后端 `/auth/semi/options`，不在前端存放服务商密钥。
注册验证联系方式后填写公开昵称和密码；Handle 由后端自动生成，不要求用户填写域名。
Semi 配置完成后显示入口，回调 `/semi-callback` 用一次性 ticket 经服务端交换会话，
校验 Rice 用户和 PDS DID 一致后再保存；登录或注册完成均保留原详情返回地址。
未配置的验证码通道不显示为注册选项；显式日志测试模式会标明没有真实短信／邮件发送。
Vite 开发代理及部署网关都需要将 `/auth/semi/` 转到 Rice；具体变量与填配置后的重启命令
在部署仓库 `compose/README.md`，前端不需要额外 API key。
